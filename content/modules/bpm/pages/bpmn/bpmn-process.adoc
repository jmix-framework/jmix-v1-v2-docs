= 流程

流程（Process）是为特定业务目标服务的活动或任务的结构化流。
在 BPMN 中，流程是核心元素，包含所有关联元素，从而展示整个工作流以及业务上下文中的交互。

== 图形表示法

流程没有可视化的表示形式。可以被包含在一个 xref:bpmn/bpmn-pools-lanes.adoc#pools[泳池] 中以使模型更清晰，但泳池并非必要。

== XML 表示

在 XML 中，流程使用 `process` 元素表示。

[source,xml]
----
  <process id="new-process" name="New process" isExecutable="true" >
    . . .
  </process>
----

// 此外，流程可能有 `processType`、`isClosed` 和 `definitionalCollaborationRef` 属性，但 Jmix BPM 会忽略这些属性。

[[properties]]
== 属性

与构成流程的元素一样，流程本身也有许多属性。当未选中任何元素时，可以在建模器中查看和编辑流程属性。

[cols="1,6", grid=rows, frame=none]
|===
|*属性*
|*描述*
|Process id
|*process id* 在流程部署时标识该流程。在运行时，被称为 *process key*。
|Name
|流程的名称。最大长度为 255 个字符。
|Candidate groups
|允许启动流程的用户组。如果用户属于该组，他们将在 xref:menu-views/start-process-view.adoc[] 视图中看到此流程定义。
|Candidate users
|允许启动流程的单个用户。如果用户是候选用户之一，他们将在 xref:menu-views/start-process-view.adoc[] 视图中看到此流程定义。
|Event listeners
|参见 xref:listeners.adoc#execution-listeners[监听器]。
|Signal definitions [[signal-definition]]
a|要创建信号定义，请设置其 *Id*、*Name* 和 *Scope*：

* `Global` 信号会发送到整个流程引擎。即，如果一个流程实例触发了一个信号事件，其他流程实例也可以响应。有助于不同流程之间的通信。
* `Process instance` 信号仅在其自身的流程实例内生效。可用于同步互斥的任务。

可以配置一个 xref:bpmn/bpmn-events.adoc#signal-events[信号事件] 元素来引用某个定义。
|Message definitions
|要创建消息定义，请设置其 id 和 name。该消息可用于 xref:bpmn/bpmn-events.adoc#message-events[消息事件] 元素。
|Error definitions
|要创建错误定义，请设置其 id 和 name。此外，可以设置 Error code。该错误可用于 xref:bpmn/bpmn-events.adoc#error-events[错误事件] 元素。
|Documentation
|对流程的描述和附加信息。
|===
