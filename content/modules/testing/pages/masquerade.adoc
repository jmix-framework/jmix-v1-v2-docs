= End-to-end UI Tests

End-to-end UI tests simulate real user interactions within a web browser, validating the entire application workflow. They run quickly and can be repeated easily, saving time compared to manual testing.

In Jmix, you can use *Masquerade* to automate end-to-end UI testing for your applications. This testing library helps you use the Page Object pattern for all parts of Jmix UI, including views, components, dialogs, notifications, and composites. It is based on https://www.selenium.dev/documentation/webdriver/[Selenium WebDriver^] and https://github.com/selenide/selenide[Selenide^].

NOTE: Masquerade is for applications that are built with *Jmix 2.6* or newer.

== Install Masquerade

Masquerade can be added as a Gradle dependency and used either inside a Jmix application or in a plain Java project.

=== Installing to a Jmix Project

To install Masquerade, follow the steps below:

. Ensure that your project uses Jmix 2.6 or newer. See the xref:studio:project.adoc#upgrading-project[Upgrading Project] section for how to upgrade using Studio.
. Specify the dependency in the project `build.gradle` file as `testImplementation`:
+
.build.gradle
----
testImplementation 'io.jmix.masquerade:jmix-masquerade'
----

=== Installing to a non-Jmix Java project

Use the same dependency:

.build.gradle
----
testImplementation 'io.jmix.masquerade:jmix-masquerade:<JMIX_VERSION>'
----

Replace the `<JMIX_VERSION>` with the version of the Jmix framework of the target project (e.g., 2.6.2). After syncing Gradle, Masquerade will be ready for use.

[[jmix_test_ids]]
== Jmix Test IDs

Masquerade may assist you in generating a special `j-test-id` (Jmix test ID) attribute for each component created with the `UiComponents` factory.
Such IDs simplify identifying elements on the page. To enable this feature, set xref:flow-ui:ui-properties.adoc#jmix.ui.ui-test-mode[jmix.ui.ui-test-mode] to true:

.application.properties
[source,properties]
----
jmix.ui.ui-test-mode = true
----

WARNING: ID generation can impact the performance. It is recommended to use this property only for a test application profile.

The default test id value will match the id already given to a component:

image::testing:masquerade-j-test-id.png[align="center", width = 848]

If a component has no id, its test id will be generated based on its data binding, `action`, or `text` attribute.

To work with an element directly by its `j-test-id`, use the `Masquerade.$j` method:

[source,java,indent=0,opts=novalidate]
----
$j("myButton").click();
----

[[wrappers]]
== Wrappers

Wrappers are classes that represent different parts of Jmix UI and encapsulate interactions with them. They help you separate test scenarios from the complexities of the UI under test. There are five types of wrappers.

[[view_wrapper]]
=== View Wrapper

A view wrapper encapsulates a view, providing a simplified and consistent interface to interact with its components. A view wrapper does not have to include all components of the corresponding view – add just those that are needed for tests.

Consider a simple view wrapper example:

[source,java,indent=0]
----
include::example$/masquerade-ex1/src/test/java/com/company/masqueradeex1/test_support/view/MyView.java[tags=MyViewWrapper]
----

<1> Annotate with `io.jmix.masquerade.TestView`. The `id` value must match the view ID specified through `@ViewController`:
+
[source, java, indent=0]
----
include::example$/masquerade-ex1/src/main/java/com/company/masqueradeex1/view/mytest/MyView.java[tags=view-controller-id]
----
+
If you don't specify an ID, then the simple class name for this view will be used as the id.
<2> Extend the `io.jmix.masquerade.sys.View` class with typing on itself. This is necessary to provide fluent API for writing tests.

[[component_wrapper]]
=== Component Wrapper

Component wrappers encapsulate components within view wrappers. To designate a field as a component wrapper, use the `@TestComponent` or `@FindBy` annotations. This is illustrated in the following example:

[source,java,indent=0]
----
include::example$/masquerade-ex1/src/test/java/com/company/masqueradeex1/test_support/view/MyView.java[tags=ComponentWrappers]
----

- `@TestComponent` indicates that the current field is a component wrapper. If the `path` value is not specified, the default value is assumed to be the value of the <<jmix_test_ids,j-test-id>> attribute for the corresponding web element.
- `@FindBy` specifies a selector to be used for this field.

TIP: Find the list of all available component wrappers in the `io.jmix.masquerade.component` package.

Component wrappers offer various methods for interacting with components. For instance, you can open an overlay or even a dialog window for an `EntityCombobox`:
