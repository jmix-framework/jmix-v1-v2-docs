= Параметры

Внешние параметры передаются извне при запуске отчета и могут использоваться как условия в наборах данных. Все внешние параметры становятся полями для каждого бэнда отчета, поэтому их можно использовать напрямую в шаблоне как поля наборов данных. Если какой-либо набор данных содержит поле с таким же именем, оно переопределяет внешний параметр в соответствующем бэнде, и отчет использует значение поля набора данных.

Внешние параметры могут передаваться вызывающим кодом при запуске отчета через xref:run-report.adoc#reports-api[API]. Также генератор отчетов может показывать диалог для ввода параметров, когда пользователь запускает отчет. В последнем случае следует описать внешние параметры на вкладке *Parameters* в редакторе отчетов во времея выполнения.

[[properties]]
== Свойства

На вкладке *Properties* можно определить свойства параметра:

* *Name* - название параметра, которое будет отображаться в форме ввода параметров при запуске отчета.
* *Alias* - псевдоним параметра, используемый для доступа к нему в наборах данных.
* *Type* - тип параметра.
* *Hidden* - флаг, определяющий, следует ли скрывать запрос параметра от пользователей.
* *Required?* - флаг, определяющий, является ли параметр обязательным.
* *Default value* - определяет значение параметра, которое будет использоваться по умолчанию, если пользователь не выберет другое значение.

Тип параметра может быть примитивным (*String*, *Number*, *Boolean*) или временным, кроме того, можно выбрать *Enumeration*, *Entity* или *List of entities* в качестве типа параметра. В зависимости от выбранного типа требуются дополнительные поля:

Если выбран тип параметра *Entity* или *List of entities*:

* *Entity* - сущность, используемая в качестве параметра.
* *Entity selection view* - необязательный идентификатор экрана, который будет использоваться для выбора экземпляров сущности. Если экран не указан, выбор будет производиться из специального общего экрана для всех сущностей.

Если выбран тип параметра *Enumeration*:

* *Enumeration* - перечисление, используемое в качестве параметра.

Если выбран временной тип параметра (*Date*, *Time* или *Date and time*):

* *Default date(time) is current* - флаг определяет, будет ли текущая метка времени использоваться в качестве значения параметра по умолчанию.

[[localization]]
== Локализация

На вкладке *Localization* можно определить название параметра для разных локалей. Для этого следует ввести пары `++locale_name = parameter_name++`, например:

[source, properties,indent=0]
----
de = das Buch
----

[[transformation]]
== Преобразование

На вкладке *Transformation* можно применить Groovy-скрипт к параметру перед его использованием в отчете.

Groovy-скрипт должен возвращать новое значение параметра. В скрипт передаются следующие переменные:

* `params` - карта параметров доступна по псевдониму `params`.

* `paramValue` - текущее значение параметра доступно в скрипте как `paramValue`.

* `dataManager` - объект типа `DataManager`, предоставляющий CRUD-функциональность.

* `metadata` - объект типа `Metadata`, предоставляющий доступ к метаданным приложения.

* `applicationContext` - объект типа `org.springframework.context.ApplicationContext`, предоставляющий доступ к управляемым бинам.

Например:

[source, plain, indent=0]
----
return "%" + paramValue + "%"
----

Также можно использовать предопределенные преобразования, которые добавляют подстановочные знаки для текстовых (String) параметров:

* `Starts with` (Начинается с),

* `Ends with` (Заканчивается на),

* `Contains` (Содержит).

image::transformation.png[align="center",width="642"]

На вкладке *Validation* можно определить Groovy-скрипт с условиями для проверки параметра, подробности смотрите ниже.

[[validation]]
== Проверка

Вы можете проверить входной параметр и/или определить межпараметрическую проверку.

. Вы можете включить проверку каждого параметра на вкладке *Validation*, установив флажок *Validate*. Логика проверки задается Groovy-скриптом. Скрипт должен проверить значение параметра и вызвать метод `showErrorMessage()`, если значение недопустимо. Этот метод покажет пользователю предупреждение с указанным сообщением об ошибках проверки отчета.
+
Скрипт получает следующие параметры:
+
* `value` - значение параметра, введенное пользователем.
+
* `applicationContext` - объект типа `org.springframework.context.ApplicationContext`, предоставляющий доступ к управляемым бинам.
+
* `currentAuthentication` - объект типа `io.jmix.core.security.CurrentAuthentication`, связанный с текущим аутентифицированным пользователем.
+
* `dataManager` - объект `DataManager` для выполнения CRUD-операций.
+
* `metadata` - объект `Metadata`, предоставляющий доступ к метаданным приложения.
+
* `showErrorMessage` - метод, который вызывает сбой проверки, если он вызывается в скрипте.
+
image::validation.png[align="center",width="642"]

. Межпараметрическую проверку можно включить, установив флажок *Validate* в разделе *Cross parameters validation* на вкладке *Parameters*. Логика проверки определяется с помощью Groovy-скрипта. Этот скрипт должен проверять согласованность значений параметров и вызывать `showErrorMessage()`, если обнаружены несоответствия. Этот метод отображает пользователю предупреждение с указанием ошибок проверки отчета.
+
В дополнение к перечисленным ранее параметрам скрипт также получает переменную `params` — карту, содержащую внешние параметры отчета.
+
image::cross-parameter-validation.png[align="center",width="834"]

[[input-parameter-def]]
== Аннотация @InputParameterDef

Аннотация `@InputParameterDef` позволяет определить входной параметр при создании отчета на этапе разработки (design time). Входные параметры передаются извне при запуске отчета и могут использоваться как условия в xref:reports:creation/bands.adoc#datasets[наборах данных].

Для реализации дополнительной логики создайте метод, аннотированный <<input-parameter-delegate,@InputParameterDelegate>>.

Аннотация @InputParameterDef имеет следующие атрибуты:

* `alias` - уникальный псевдоним, используемый для доступа к параметру в наборах данных.
* `name` - имя входного параметра. Вы можете использовать префикс msg:// для ссылки на xref:localization:message-bundles.adoc[локализованное сообщение].
* `required` - указывает, является ли параметр обязательным. По умолчанию: `false`.
* `type` - тип данных параметра, определяемый перечислением `ParameterType`:
** `DATE` - дата без времени. Класс значения: `java.util.Date`.
** `TEXT` - текстовая строка. Класс значения: `String`
** `ENTITY` - отдельный экземпляр сущности (persistent или DTO).
** `BOOLEAN` - значение `Boolean`.
** `NUMERIC` - число с необязательной дробной частью. Класс значения: `Double`.
** `ENTITY_LIST` - `java.util.Collection` экземпляров сущностей (persistent или DTO).
** `ENUMERATION` - значение перечисления.
** `DATETIME` - дата со временем. Класс значения: `java.util.Date`.
** `TIME` - время. Класс значения: `java.util.Date`.
* `enumerationClass` - класс перечисления для параметров типа `ParameterType.ENUMERATION`.
* `defaultValue` - строковое представление значения по умолчанию, используемое, если не выбрано другое значение. Для сложных типов рассмотрите использование делегата `io.jmix.reports.yarg.structure.DefaultValueProvider`.
* `defaultDateIsCurrent` - указывает, будет ли текущая метка времени использоваться в качестве значения по умолчанию для типов `ParameterType.DATE`, `ParameterType.TIME`, `ParameterType.DATETIME`. По умолчанию: `false`.
* `entity` - дополнительные параметры для типов `ParameterType.ENTITY` и `ParameterType.ENTITY_LIST`, определяемые аннотацией <<entity-parameter-def,@EntityParameterDef>>.
* `predefinedTransformationEnabled` - включает предопределенное преобразование для параметров типа `ParameterType.TEXT`, полезно, когда параметр используется в условиях запроса для SQL и JPQL наборов данных. По умолчанию:  `false`.
* `predefinedTransformation` - тип предопределенного преобразования для параметров типа `ParameterType.TEXT`, определяемый перечислением `PredefinedTransformation`: `STARTS_WITH`, `CONTAINS`, `ENDS_WITH`. По умолчанию: `CONTAINS`.
* `hidden` - определяет, должен ли запрос параметра быть скрыт от пользователей. По умолчанию: `false`.

[[input-parameter-delegate]]
== Аннотация @InputParameterDelegate

Аннотация `@InputParameterDelegate` определяет метод-делегат, который реализует логику, связанную с входным параметром.

*Требования*:

* Метод не должен иметь параметров.
* Метод должен возвращать один из поддерживаемых функциональных интерфейсов.

Поддерживаемые интерфейсы:

* `DefaultValueProvider` - предоставляет значение по умолчанию для параметра.
* `ParameterValidator` - проверяет значение параметра.
* `ParameterTransformer` - преобразует значение параметра.

Аннотация `@InputParameterDelegate` имеет атрибут `alias`, который является псевдонимом входного параметра, объявленного в текущем определении отчета.

[[entity-parameter-def]]
== Аннотация @EntityParameterDef

Определяет дополнительные параметры для входных параметров типа `ParameterType.ENTITY` и `ParameterType.ENTITY_LIST`.

Имеет следующие атрибуты:

* `entityClass` - класс сущности параметра. По умолчанию: `void.class`.
* `component` - тип UI-компонента, используемого для ввода значений параметра `ParameterType.ENTITY` при запуске отчета из пользовательского интерфейса. Атрибут component принимает следующие значения перечисления `EntityInputComponent`:
** `OPTION_LIST` - используется компонент xref:flow-ui:vc/components/entityComboBox.adoc[EntityComboBox]. Опции загружаются с помощью JPQL-запроса.
** `LOOKUP_VIEW` - используется компонент xref:flow-ui:vc/components/entityPicker.adoc[EntityPicker], который открывает экран выбора. Значение по умолчанию.
* `optionsQueryJoin` - предложение JOIN, добавляемое к JPQL-запросу, который загружает опции.
* `optionsQueryWhere` - предложение WHERE, добавляемое к JPQL-запросу, который загружает опции.
* `lookupViewId` -  ID экрана выбора, открываемого для выбора значений параметров `ParameterType.ENTITY` или `ParameterType.ENTITY_LIST`.
