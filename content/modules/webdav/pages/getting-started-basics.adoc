= Часть 1. Начальный уровень

В этой главе вы создадите:

* Сущность `WebdavDocumentWrapper` с атрибутом типа `WebdavDocument`.
* CRUD-экраны, включая UI-компонент для загрузки документа WebDAV.

Вы внесете необходимые изменения, чтобы обеспечить открытие и редактирование загруженных файлов WebDAV в настольных офисных приложениях (Word, Excel, LibreOffice и т. д.).

[[create-webdavdocumentwrapper-entity]]
== Создание сущности WebdavDocumentWrapper

Создадим сущность `WebdavDocumentWrapper`.

TIP: Подробные инструкции по созданию сущностей можно найти в разделе xref:tutorial:simple-crud.adoc[Простой CRUD] самоучителя.

В окне инструмента *Jmix* нажмите *New* (image:add.svg[]) -> *JPA Entity*. Введите `WebdavDocumentWrapper` в поле *Class*.

Сущность `WebdavDocumentWrapper` имеет следующие атрибуты:

* `description` типа `String`.
* `lastModifiedBy` типа `String`.
* `lastModifiedDate` типа `OffsetDateTime`.
* `webdavDocument` типа `WebdavDocument`:
+
image::webdav-document-attr.png[align="center"]

[[create-webdavdocumentwrapper-crud]]
== Создание CRUD-экранов

Сгенерируем CRUD-экраны для сущности `WebdavDocumentWrapper`.

Нажмите *Views → Create view* на панели действий в верхней части дизайнера сущностей.

На первом шаге мастера создания экранов выберите шаблон `Entity list and detail views`. Нажмите *Next*.

Примите предложенные значения на первых двух шагах мастера.

На шаге *Entity list view fetch plan* добавьте атрибут `webdavDocument` к выборке:

image::create-doc-wrapper-list-fetch.png[align="center",width="997"]

Теперь вы можете быть уверены, что сущность `WebdavDocument`, на которую есть ссылка, будет загружена вместе с корневой сущностью `WebdavDocumentWrapper` и отображена в экране списка.

CAUTION: Если атрибут отсутствует в фетч-плане, Studio не создает для него визуальный компонент в сгенерированных экранах.

Нажмите *Next*.

На шаге *Entity detail view fetch plan* удалите из выборки атрибуты `lastModifiedBy` и `lastModifiedDate`. Эти атрибуты будут заполняться автоматически, поэтому отображать их на экране деталей было бы избыточно.

//image::create-doc-wrapper-detail-fetch.png[align="center",width="997"]

Нажмите *Next*.

Studio автоматически сгенерирует два экрана: `WebdavDocumentWrapper.list` и `WebdavDocumentWrapper.detail`, и откроет их исходный код.

[[add-webdavDocumentUploadField]]
== Добавление WebdavDocumentUploadField на экран

Найдите `webdav-document-wrapper-detail-view.xml` в окне инструмента *Jmix* и дважды щелкните на нем. Откроется дизайнер экрана:

image::wdw-detail-view.png[align="center",width="1552"]

Обратите внимание, что для отображения атрибута `webdavDocument` используется компонент `entityPicker`.
Если вы хотите отобразить специальный компонент, предназначенный для работы с документами, добавьте UI-компонент xref:webdav:ui-components.adoc#webdav-document-upload-field[webdavDocumentUploadField] в XML-дескриптор.

Удалите описание компонента `entityPicker` из XML-дескриптора и поместите курсор после компонента `textField`. Затем нажмите *Add Component* на панели действий, найдите элемент `WebdavDocumentUploadField` и дважды щелкните на нем.

image::add-wd-upload-field.png[align="center",width="719"]

Новый элемент `webdavDocumentUpload` будет добавлен под элементом `formLayout` как на панели структуры *Jmix UI*, так и в XML. Настройте атрибуты `id`, `colspan` и `property`, как показано ниже.

[source,xml,indent=0]
----
            <textField id="descriptionField"
                       property="description"
                       colspan="2"/>
            <webdav:webdavDocumentUpload id="webdavDocumentField"
                                         property="webdavDocument"
                                         colspan="2"/>
----

[[running-application]]
== Запуск приложения

После создания сущности и CRUD-экранов для нее вы можете запустить приложение, чтобы увидеть новую функциональность в действии.
Нажмите кнопку *Debug* (image:start-debugger.svg[]) на главной панели инструментов.

Перед запуском приложения Studio сравнивает модель данных проекта со схемой базы данных. Поскольку вы создали новую сущность, Studio автоматически генерирует Liquibase changelog, отражающий соответствующие изменения базы данных (например, создание таблицы `WEBDAV_DOCUMENT_WRAPPER`):

image::db-wd-wrapper.png[align="center",width="1157"]

Studio выполнит changelog в вашей базе данных, а затем соберет и запустит приложение:

После запуска приложения перейдите по адресу `++http://localhost:8080++` в веб-браузере и войдите в приложение с учетными данными `admin/admin`.

Выберите пункт `Webdav document wrappers` в меню `Application`. Откроется экран `Webdav document wrapper.list`. Нажмите *Create*. Откроется экран `Webdav document wrappers.detail`. Помимо текстового поля, используемого для описания файла, вы увидите встроенный компонент дополнения WebDAV для загрузки файлов. Попробуйте загрузить файл с помощью этого компонента:

После нажатия кнопки *OK* вы будете перенаправлены на экран списка. Как видите, колонка *Webdav document* отображает идентификатор файла. В следующем разделе мы покажем, как отобразить в таблице данных ссылку на документ вместо его идентификатора.

[[configuration]]
== Конфигурация

Для авторизации настольных приложений на сервере должен быть включен HTTPS. Ниже приведены простые инструкции по настройке HTTPS в вашей среде разработки.

[IMPORTANT]
====
Самоподписанные сертификаты подходят только для тестовых целей. При работе с production-приложениями необходимо использовать SSL-сертификаты, выпущенные доверенным центром сертификации.
====

[[keystore-file]]
=== Создание файла хранилища ключей

. Сгенерируйте хранилище ключей с помощью https://docs.oracle.com/en/java/javase/11/tools/keytool.html[утилиты keytool^], входящей в состав JDK:
+
[source,text]
----
keytool -genkey -keyalg RSA -alias localhost -keystore localhost.jks -validity 365 -keysize 2048
----
+
У вас запросят пароль хранилища ключей, а затем некоторые имена. Запомните пароль и имена.

. Экспортируйте сертификат из хранилища ключей:
+
[source,text]
----
keytool -export -keystore localhost.jks -storepass <password> -alias localhost -file localhost.cer
----
+
Используйте пароль, введенный на первом шаге, вместо `<password>`.

. Зарегистрируйте сертификат как доверенный в вашей операционной системе.
+
* В операционной системе Windows:
+
1. Нажмите клавишу `Windows` + `R`, чтобы открыть диалоговое окно *Run*, затем введите `"certmgr.msc"` и нажмите *Enter*. Откроется *Certificate Manager*.

2. В левой панели *Certificate Manager* разверните папку *Trusted Root Certification Authorities*.

3. Щелкните правой кнопкой мыши на папке и выберите *All Tasks > Import...* в контекстном меню. Откроется *Certificate Import Wizard*.

4. В *Certificate Import Wizard* нажмите *Next*, затем перейдите к месту хранения файла сертификата. Выберите файл сертификата и нажмите *Next*.

5. Выберите опцию поместить сертификат в хранилище *Trusted Root Certification Authorities* и нажмите *Next*.

6. Проверьте информацию и нажмите *Finish*, чтобы завершить процесс импорта.

7. Вы должны увидеть сообщение об успешном завершении импорта. Нажмите *OK*, чтобы закрыть мастер.
+
После выполнения этих шагов сертификат будет зарегистрирован как доверенный в операционной системе Windows.
* В macOS:
1. Дважды щелкните на файле `localhost.cer` в Finder. Откроется приложение *Keychain Access*.
2. Найдите свой сертификат по имени, введенному на первом шаге как "имя и фамилия", на вкладке *Certificates*.
3. Дважды щелкните на сертификате и выберите *Trust -> When using this certificate: Always Trust*.

[[configuring-server]]
=== Настройка сервера

В этом разделе описано, как использовать сертификат, сгенерированный в предыдущем разделе, в вашем приложении, когда оно запускается из IDE или как исполняемый JAR.

. Создайте директорию `src/main/resources/<base-package>/keystore` и скопируйте в нее `localhost.jks`.

. Задайте следующие свойства в файле `application.properties`, заменив `<base-package>` и `<password>` на реальные значения:
+
[source,properties,indent=0]
----
# Enables HTTPS
server.ssl.enabled=true
# The format used for the keystore
server.ssl.key-store-type = JKS
# The path to the keystore containing the certificate
server.ssl.key-store = classpath:<base-package>/keystore/localhost.jks
# The password used to generate the keystore
server.ssl.key-store-password = <password>
# The alias mapped to the certificate
server.ssl.key-alias = localhost

# Changes the server's port
server.port = 8443
----
+
[NOTE]
====
Значение `<base-package>` в пути к хранилищу ключей (свойство `server.ssl.key-store`) должно быть указано как путь с разделителями в виде слэшей:
----
server.ssl.key-store = classpath:com/example/demo/keystore/localhost.jks
----
====
. Откройте главный класс приложения и измените метод `printApplicationUrl()`. После настройки HTTPS URL должен быть изменен на `https://`:
+
[source,java,indent=0]
----
@EventListener
    public void printApplicationUrl(final ApplicationStartedEvent event) {
        LoggerFactory.getLogger(DemoApplication.class).info("Application started at "
                + "https://localhost:"
                + environment.getProperty("local.server.port")
                + Strings.nullToEmpty(environment.getProperty("server.servlet.context-path")));
    }
----

После выполнения описанных выше инструкций запустите приложение и убедитесь, что загруженные документы открываются в настольных офисных приложениях.

== Итоги

В этом разделе вы создали самую простую функциональность приложения: управление оболочками документов WebDAV.

Вы узнали, что:

* Компонент xref:webdav:ui-components.adoc#webdav-document-upload-field[WebDAVDocumentUploadField] включает удобные встроенные инструменты для просмотра и загрузки документов WebDAV.
* Чтобы включить открытие и редактирование документов WebDAV в настольных офисных приложениях, необходимо настроить <<configuration,HTTPS>> для вашего веб-приложения.
