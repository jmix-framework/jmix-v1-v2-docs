[[visual-components]]
== 可视化组件

搜索扩展组件提供两个 UI 组件：xref:search-field-component.adoc[SearchField] 和 xref:full-text-filter-component.adoc[FullTextFilter]。

[[search-strategies]]
== 搜索策略

搜索策略定义如何处理搜索词。基本上是使用一些查询语句配置搜索请求。

xref:search-field-component.adoc[SearchField] 和 xref:full-text-filter-component.adoc[FullTextFilter] 组件支持下列内置的搜索策略：

* `startsWith`
+
NOTE: 该策略 **仅当** 在至少一个索引定义上启用了 xref:index-definitions.adoc#extended-search[@ExtendedSearch] 时才可用。
+
对预索引的 Edge N-Gram 子字段执行基于前缀的搜索：

** 从生成 xref:search-properties.adoc#jmix.search.minPrefixLength[jmix.search.min-prefix-length]（默认：`3`）到 xref:search-properties.adoc#jmix.search.maxPrefixLength[jmix.search.max-prefix-length]（默认：`8`）所有长度的前缀。
** 提供比通配符查询更快的性能。
** 当输入超过最大前缀长度时，如果 xref:search-properties.adoc#jmix.search.wildcardPrefixQueryEnabled[jmix.search.wildcard-prefix-query-enabled] = `true`（默认），则回退到通配符查询。
+
NOTE: 对短于 `jmix.search.min-prefix-length` 的词条始终返回空结果。

* `phrase`
+
执行精确短语匹配：

** 文档必须将所有搜索词按 **准确顺序** 包含在同一字段内。
** 相当于搜索引擎中的传统词组查询。
** 非常适合姓名、头衔或准确词语的搜索。

* `anyTermAnyField`
+
对所有字段执行析取式词项匹配：

** 返回在 **任何** 索引字段中匹配 **任意** 输入词项的文档。
** 词项之间使用 OR 逻辑组合。
** 向后兼容的默认策略。

+
默认情况下设置此策略。

CAUTION: `allTermsAnyField` 和 `allTermsSingleField` 已弃用并在 UI 中隐藏，但如有需要可以重新实现。

=== 自定义搜索策略

另外，也可以创建自己的搜索策略。为此，首先创建一个实现下列接口之一的 Spring bean：

* `OpenSearchSearchStrategy` - 如果使用 OpenSearch。
* `ElasticsearchSearchStrategy` - 如果使用 Elasticsearch。

然后需要实现两个方法：

* `String getName()` - 返回策略的唯一名称。

* `void configureRequest(SearchRequest.Builder requestBuilder, SearchContext searchContext)` - 根据需要使用传入的 builder 配置所需的搜索请求。

[[fts-condition-in-filter-component]]
== 过滤器组件中的全文搜索条件

当项目中添加了搜索扩展组件后，xref:flow-ui:vc/components/genericFilter.adoc[GenericFilter] 组件的 *Add condition（添加条件）* 弹窗会出现一个新的条件：

image:search:add_condition.png[align="center",width="1151"]

在 *Full-text filter condition editor（全文过滤条件编辑）* 对话框中，你可以为全文过滤器设置标题并选择一个搜索策略。如果未设置，则使用默认策略。

image:search:condition_editor.png[align="center",width="642"]

与过滤器关联的列表组件中的记录会基于全文搜索结果过滤。
